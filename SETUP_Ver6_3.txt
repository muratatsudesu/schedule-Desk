Q.T.S Scheduler Ver.6.3 初回設定

このVer.6.3では、本物のログインと完全非公開のプライベート予定を使います。
GitHubへアップロードするだけではログインできないため、Firebaseで初回設定が必要です。

【重要】
既存の予定は schedules コレクションから削除・移動しません。
Ver.6.2までの予定は、そのまま「共有予定」として残ります。

■ 1. Firebase Authenticationを有効化
1) Firebase Consoleで qts-schedule を開く
2) Authentication（認証）を開く
3) 「始める / Get started」
4) Sign-in method（ログイン方法）
5) Email/Password（メール/パスワード）を有効化して保存

■ 2. 利用者アカウントを作る
Authentication → Users（ユーザー）→ Add user から、
利用する人のメールアドレスとパスワードを登録します。

まずは村口さん1名だけ作って動作確認しても構いません。
確認後、金子さん・寺門さんを追加できます。

初回ログイン時に、Q.T.S Scheduler内で
「村口 / 金子 / 寺門」から本人の名前を1回だけ選びます。

■ 3. GitHubへVer.6.3をアップロード
このZIP内のファイルを、これまでと同じ方法でGitHubへアップロードし、
同名ファイルを置き換えます。

この段階でまずログインし、
以前の共有予定が表示されることを確認してください。

■ 4. Firestoreルールを安全版へ変更
共有予定が表示されることを確認してから行います。

Firebase Console
→ Firestore Database
→ ルール（Rules）

このZIPの「firestore.rules.txt」の内容を貼り付け、
「公開 / Publish」を押します。

このルールを公開した後は、
・共有予定：ログインした利用者だけ閲覧可能
・プライベート予定：作成した本人だけ閲覧可能
になります。

【プライベート予定】
予定登録画面の
「🔒 プライベート予定にする」
をONにして保存します。

プライベート予定は
users/{本人UID}/privateSchedules
という本人専用領域に保存されます。

他の利用者の画面には
タイトル、時間、予定あり表示なども一切出ません。

■ 安全な導入順
1) Authentication有効化
2) 村口さんのユーザーを1名作成
3) Ver.6.3をGitHubへアップロード
4) ログインして既存予定が見えることを確認
5) firestore.rules.txt をFirebaseへ公開
6) プライベート予定を1件テスト
7) 別ユーザーを作り、その予定が見えないことを確認

分からない画面が出た場合は、その画面のスクリーンショットをChatGPTへ送ってください。
